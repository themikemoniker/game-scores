# How I built Game Scores · Cómo construí Game Scores

A short Q&A about the process, and how it compares with Matt Pocock's skills flow
(grill → PRD → issues → TDD). English on the left, Spanish on the right.

| English | Español |
| --- | --- |
| **What is Game Scores?** | **¿Qué es Game Scores?** |
| A small, hand-picked Catalog of Games ranked by a Score I designed. Every Game page shows the working: each External Rating, how many reviews it rests on, how far it gets pulled toward 70, and its share of the Score. | Un Catálogo pequeño de Juegos, elegidos a mano y ordenados por una Puntuación que diseñé yo. Cada página muestra el cálculo: cada Valoración externa, cuántas reseñas la respaldan, cuánto se acerca a 70 y cuánto pesa en la Puntuación. |
| **Where did you start: code or questions?** | **¿Por dónde empezaste: código o preguntas?** |
| Questions. I started with a grilling session: the agent asked me about the product until we agreed on every decision. That became a spec with user stories, implementation decisions, testing decisions and an explicit "out of scope" list. | Por las preguntas. Empecé con una sesión de *grilling*: el agente me preguntó sobre el producto hasta que acordamos cada decisión. Eso se convirtió en una especificación con historias de usuario, decisiones de implementación, decisiones de pruebas y una lista explícita de lo que queda fuera. |
| **How does that compare with Pocock's flow?** | **¿Cómo se compara con el flujo de Pocock?** |
| It's the same spine: grill me, write the PRD, split it into issues. Two differences: my issues are numbered markdown files in the repo, not GitHub issues, and each one is a vertical slice that deploys working on its own. | Es la misma columna vertebral: *grill me*, escribir el PRD, dividirlo en tickets. Dos diferencias: mis tickets son archivos markdown numerados dentro del repo, no *issues* de GitHub, y cada uno es una porción vertical que se puede desplegar funcionando por sí sola. |
| **Did you use TDD?** | **¿Usaste TDD?** |
| Partly. Pocock's flow ends in red-green TDD. I kept his idea of testing through one deep module: all the Score logic sits behind a single function, Catalog read, and the tests drive only that seam. The Sheet, IGDB and auth are thin glue that I checked by hand. | En parte. El flujo de Pocock termina en TDD rojo-verde. Yo me quedé con su idea de probar a través de un único módulo profundo: toda la lógica de la Puntuación está detrás de una sola función, la lectura del Catálogo, y las pruebas solo usan esa interfaz. La hoja de cálculo, IGDB y la autenticación son una capa fina que revisé a mano. |
| **What about the words on the page?** | **¿Y las palabras de la página?** |
| That's the glossary, Pocock's "ubiquitous language" idea. Game, Catalog, Score, Unscored, Tag, Quiz, Match: each term has one meaning and a list of words to avoid. It kept the code, the UI and the Spanish translation consistent. | Eso es el glosario, la idea de "lenguaje ubicuo" de Pocock. Juego, Catálogo, Puntuación, Sin puntuación, Etiqueta, Quiz, Coincidencia: cada término tiene un solo significado y una lista de palabras que evitar. Así el código, la interfaz y la traducción al español se mantuvieron coherentes. |
| **What did you add that isn't in his flow?** | **¿Qué añadiste que no está en su flujo?** |
| Design. I used the Impeccable skill for a direction round: it sketched four visual worlds, I picked "Cross Review Weekly", after Japanese game magazines, and a separate reviewer agent scored the build against that direction before it shipped. | Diseño. Usé la *skill* Impeccable para una ronda de dirección visual: propuso cuatro mundos, elegí "Cross Review Weekly", inspirado en las revistas japonesas de videojuegos, y un agente revisor aparte evaluó el resultado contra esa dirección antes de publicarlo. |
| **How did the Quiz feature go through the same process?** | **¿Cómo pasó el Quiz por el mismo proceso?** |
| Three grilling rounds. The first one found the real problem: IGDB marks 15 of my 16 Games as "Adventure", so Genres couldn't tell them apart. We decided on owner-written Tags instead. Then came new spec stories, new glossary terms and two tickets: Tags, then Quiz and Matches. Each was built and tested, then reviewed and deployed. | Tres rondas de *grilling*. La primera encontró el problema real: IGDB marca 15 de mis 16 Juegos como "Aventura", así que los Géneros no servían para distinguirlos. Decidimos usar Etiquetas escritas por mí. Después vinieron nuevas historias en la especificación, nuevos términos en el glosario y dos tickets: Etiquetas, y luego Quiz y Coincidencias. Cada uno se construyó y se probó, y después se revisó y se desplegó. |
| **I accepted most recommended answers. Was the grilling still worth it?** | **Acepté la mayoría de las respuestas recomendadas. ¿Valió la pena el grilling?** |
| Yes. The value isn't in arguing every answer. It's that every decision gets named before code exists: what happens with a typo in a Tag, whether Sync wipes Tags, what the page says when nothing matches. Saying "defaults" takes a second once the question is on the table. | Sí. El valor no está en discutir cada respuesta, sino en que cada decisión se nombra antes de que exista el código: qué pasa con una Etiqueta mal escrita, si la sincronización borra las Etiquetas, qué dice la página cuando nada coincide. Decir "por defecto" lleva un segundo una vez que la pregunta está sobre la mesa. |
| **Where does your process differ most from Pocock's?** | **¿Dónde se diferencia más tu proceso del de Pocock?** |
| In the loop. His flow aims at agents working through the issues on their own, AFK. Mine stayed in one conversation with me in it, because a portfolio piece is about judgment: picking the Games, approving Tags, choosing the design. I'd use his AFK loop for bigger, more mechanical work. | En el ciclo. Su flujo apunta a que los agentes resuelvan los tickets por su cuenta, sin supervisión (AFK). El mío se quedó en una sola conversación conmigo dentro, porque en un proyecto de portafolio lo que importa es el criterio: elegir los Juegos, aprobar las Etiquetas, decidir el diseño. Usaría su ciclo AFK para trabajo más grande y más mecánico. |
| **What would you tell someone trying this?** | **¿Qué le dirías a alguien que quiera probarlo?** |
| Write the spec and the glossary before any code, keep each ticket small enough to deploy, and test one seam well instead of everything a little. The agent writes fast; your job is to make the decisions it shouldn't. | Escribe la especificación y el glosario antes de cualquier código, mantén cada ticket lo bastante pequeño como para desplegarlo, y prueba bien una sola interfaz en lugar de todo un poco. El agente escribe rápido; tu trabajo es tomar las decisiones que no le tocan a él. |
